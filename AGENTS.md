# AGENTS.md

## What this repo is

A collection of minimal, self-contained demos that reproduce `Java` concurrency
bugs — "seeing is believing". each demo is a class with a `main` method that
intentionally exhibits a race, deadlock, livelock, visibility failure, etc.

## Commands

```bash
# Build (what CI runs: .github/workflows/ci.yaml, Java 8/11/17/21/25 matrix)
./mvnw -V --no-transfer-progress clean package

# Compile only
./mvnw compile

# Run a single demo (the standard way to run any demo)
./mvnw compile exec:java -Dexec.mainClass=fucking.concurrency.demo.WrongCounterDemo
```

- Many demos **never terminate** (deadlock, livelock, `HashMap` hang) or
  intentionally print a wrong result. That is the point of the demo,
  not a failure. Run them with a timeout and interrupt them, e.g.
  `timeout 10s ./mvnw compile exec:java -Dexec.mainClass=...`
  — don't leave them running and don't treat a hang as a broken build.
- Some demos only reproduce on specific hardware/JVM/JIT conditions
  (e.g. `FinalInitialDemo` instruction reordering, `InvalidLongDemo` tearing)
  and may print the "correct" outcome on a given run.

## Architecture

- `src/main/java/fucking/concurrency/demo/` — one top-level class per demo,
  e.g. `NoPublishDemo`, `WrongCounterDemo`, `SymmetricLockDeadlockDemo`,
  `CyclicThreadPoolDeadLockDemo`. Classes are flat and independent;
  there is no shared framework.
  - `demo/util/LoadMaker.java` — only shared helper: spins CPU load to make
    races more reproducible (`makeLoad()` / `stopLoad()`).
- Demo shape: a `main` method starts 2+ threads, runs the buggy interleaving,
  then either checks state and prints a wrong-result message
  or simply hangs/never reaches the check.
- Docs are the index of demos:
  - `README.md` (English) and `docs/zh-CN/README.md` (Chinese translation)
    each document every demo with the same four subsections:
    **Demo description**, **Problem statement**,
    **Quickly run** (the `mvnw ... exec:java` command),
    plus a link to the demo source.
    **When adding or renaming a demo, update both files**
    and keep the source path links correct.
  - The TOC in both READMEs is generated by `doctoc`
    (between `START doctoc` / `END doctoc` comments)
    — regenerate rather than hand-editing.
- `pom.xml` — plain single-module jar, `source`/`target` 1.8,
  enforcer requires JDK ≥ 8 and Maven ≥ 3.5.0;
  plugin versions pinned in `pluginManagement`.
  `exec-maven-plugin` is invoked by prefix, not declared.
